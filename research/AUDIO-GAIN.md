# 原版音频增益与过载混音

原先独立混音器无条件使用0.95峰值限幅器，会压低过载样本并改变峰值前后的包络。8组新的原版受控导出证明默认混音下应保留相加波形到最终PCM打包，再由整数输出范围削波；移除隐式限幅器后，本组完整PCM24流均逐字节相同。此结论不覆盖配置了动态处理器、插件或不同总线状态的工程。

## 实验与来源

只操作专用`REA Reference · 2026-10-21`工程。自有48kHz、16位、单声道WAV各96000样本：恒定+20000、恒定-20000、幅度30000的440Hz正弦，正弦由Python整数round生成。时间线24fps，源区间0至48帧，输出音频专用QuickTime MOV、双声道48kHz PCM24。Lua脚本见`probe_resolve_audio_gain.lua`，每个片段用`SetProperty('AudioVolume', gain)`设置原版dB增益，再保存属性、时间和任务ID读回。

8个任务由原始ID查询均Complete/100%，`rendering=false`，没有重复创建任务。运行记录及状态保存在本机`audio-gain-runtime.json`、`audio-gain-status.json`。状态提取器会同时发现同一保存blob内的实验载荷，状态读取因此明确筛选`after.audio_gain_status`，不把邻近载荷当作状态记录。

一致性SQLite backup快照`reference-audio-gain.sqlite`由既有REA CLI检查，Evidence ID `ev_4d99d87f632c30ca72a3c83a519bafb8149414dbe9e377fd5458227a6f3f5e10`。REA范围是数据库身份、结构和3行采样；行为结论来自已保存Lua读回与实际导出的完整PCM，不把数据库检查描述为算法证明。该轮会话没有REA MCP工具，复用已安装CLI，未修改MCP配置或安装依赖。数据库、原版程序和本机报告不发布。

## 观察与推断

| 案例 | 原版配置 | 完整输出结果 |
|---|---|---|
| dc_unity | +20000，0dB | 正文保持源幅度，默认72样本边缘 |
| dc_minus6 | +20000，-6dB | 增益转换后正文和边缘一致 |
| dc_plus6 | +20000，+6dB | 到达正PCM24满量程8388607 |
| negative_plus6 | -20000，+6dB | 到达负PCM24满量程-8388608 |
| sine_plus6 | 正弦，+6dB | 正负峰值削波，完整波形一致 |
| dc_overlap | 两轨+20000，0dB，同起点 | 和信号到达正满量程 |
| dc_cancel | 两轨相反DC，0dB，同起点 | 全部样本为0 |
| dc_stagger | 两轨+20000，第二轨晚12帧 | 叠加时削波，离开叠加后恢复原幅度 |

这里的“相加至整数打包再削波”是能解释本组全流数据的处理模型，不声称已读取原版内部DSP实现。移除旧限幅器前8组中3组相同、5组失败；移除后8组完整输出相同，不使用抽样、对齐修补或容差。自动边缘规则和最近偶数PCM24量化保持不变。原版dB数值在当前GT Studio线性volume接口中转换为`10**(dB/20)`，尚未将界面线性音量控件改成原版dB控件。

## 实现与验证

`engine.py`以不归一化的amix相加，移除无条件alimiter，保留浮点混音到既有PCM24量化及整数编码。8组新夹具`tests/fixtures/audio-gain.json`只含自有合成信号的完整压缩PCM32载体、摘要、输入定义及精确任务ID；测试生成对应输入并比较全流字节。原版音频专用MOV与独立引擎黑色视频MOV仅比较PCM，不宣称容器相同。

`compare_native_audio_gain.py --run-name NAME`通过配置中的stdio MCP启动私有工程服务，逐组重建、设置增益、保存重开并导出。8组全流相同，53个公开工具，见本机`audio-gain-comparison-no-limiter.json`。此前8组音频边缘夹具也仍全部精确通过。本机完整287项通过，0失败、0跳过，50.78秒；远程CI按对应提交记录独立核对。
