# 原版片段声像：稳定增益与启动平滑

已实现48kHz静态片段声像，接入工程持久化、检查器和既有MCP属性接口。14组原版PCM24完整导出逐字节相同，3组PCM32基准也约束了内核运算。原版端点不是普通左右平衡，启动平滑的float32分组与停止规则同样影响结果。其他采样率、动态参数和一般Fairlight仍未完成。

## 原版操作与证据

只操作专用`REA Reference · 2026-10-21`，输入均为自有两秒48kHz/S16 WAV：单声道恒定4096，双声道左4096/右8192。时间线24fps，0至48帧，AudioVolume=0dB、AudioPanEnabled=true，默认双声道总线。原版stub声明AudioPan范围-100至100；原版检查器也实际回显`100.0 声像`，没有把大数值误当作另一个参数单位。

`probe_resolve_audio_pan.lua`设置单声道9个位置（-100/-75/-50/-25/0/25/50/75/100）和双声道5个位置（-100/-50/0/50/100）。14个原始任务均Complete/100%，最终rendering=false。实际输出由解码器确认音频专用MOV、48kHz双声道pcm_s24le。

`probe_resolve_audio_pan32.lua`追加单声道25/50/100三个位置，明确请求AudioBitDepth=32。3个原始任务也均Complete/100%，解码器实际确认pcm_s32le，不能只凭设置返回成功判断32位格式。其余轨道和用户工程未改动。创建脚本、精确任务状态脚本均保留在scripts目录。

保存标记及SQLite一致性backup快照保留运行记录；REA CLI对24位实验快照的身份、表结构与3行采样给出Evidence `ev_0af04e8e3cd315bd374a255f66738ea9604b76dfe01d0d2f79d5ac05649082e7`。范围是快照检查，不证明DSP实现。行为结论来自原版读回及17个实际PCM流。

## 稳定区间观察

同一输入声道上的稳定幅度比可换算为下列分贝。表中的值来自完整流中5000至尾部72样本前恒定不变的区间，分贝显示取一位；完整数字和PCM见夹具。

| 单声道声像 | 左声道增益dB | 右声道增益dB |
|---:|---:|---:|
| -100 | +6.0 | -6.0 |
| -75 | +4.9 | -6.0 |
| -50 | +3.5 | -6.0 |
| -25 | +1.9 | -2.5 |
| 0 | 0.0 | 0.0 |
| 25 | -2.5 | +1.9 |
| 50 | -6.0 | +3.5 |
| 75 | -6.0 | +4.9 |
| 100 | -6.0 | +6.0 |

双声道选定位置分别作用在左右输入上：右输入为左输入两倍时，右输出保持相应两倍关系。尚不能由DC推断一般声像、声道串混或其他布局都相同。

这些点与`1±pan/100`换算dB、量化到0.1dB并限制在±6dB的模型一致，但这仍是有限点上的推断，未确立连续参数算法。特别是端点并非单侧静音，不应替换成普通balance/equal-power公式。

## 启动过程与未通过的模型

除既有72样本自动片段边缘外，非零声像在样本72至128仍是单位增益，从样本129才开始改变。以+100单声道为例，左声道到样本3218才完全稳定，右声道到样本3554才稳定。第1000样本左右幅度比约0.587630和1.822786，不能当作最终系数。

32位输出揭示更多低位：+100左稳定系数0.5011872053146362、右1.9952622652053833。将3组32位完整流最近偶数量化为24位，与对应24位原版输出全部逐字节一致，0个差异标量。这验证了两批精度与既有PCM24量化证据的关系。

分析脚本保留一个明确失败的假设：用实测稳定值为目标，前128样本单位增益，之后双精度一阶递推alpha=0.00200801，剩余差小于0.001时直接到目标。3组/6声道的启动比较仍各有408至807个差异样本，最大差异约268448至272928个S32载体单位。部分大差异来自停止平滑的边界，并非可由放宽一位容差消除。该系数只是近似拟合，不用于生产渲染，也不宣称是原版系数。

## 可复跑的材料

`research/audio-pan-fixtures.json`仅含17组自有信号的完整压缩PCM、摘要、输入定义、任务状态和属性读回，不包含原版数据库、二进制、音乐或用户媒体。约370KiB。

运行`.venv/bin/python scripts/analyze_native_audio_pan.py`可离线校验完整PCM摘要、稳定区间、启动位置、32至24位全流关系以及失败模型的残差。加`--capture`时才读取本机已完成的原版任务材料重新生成夹具，并验证源WAV的每个样本确实是上述自有恒定信号。默认分析不需要原版安装、REA、FFmpeg或网络。

以上记录保留首轮研究及失败模型的历史。后续实现与当前边界如下。


## 独立实现与验证

深度REA函数分析实际返回provider_unavailable：本机Ghidra/Hopper/IDA/Kuna没有可用配置。保留诊断，没有安装或改写配置。随后用系统nm/otool读取选定音频库的导出符号和少量函数；未把系统反汇编称为REA成功反编译。`libBMDAudioPlugins.dylib` SHA256为`758be78d974d77752b2c71e19a7d17cd520d1a96568486dd72dca0e30cbe133a`。未发布原版库或反汇编文本。

选定arm64切片的MixPole::ScaleInputSmooth位于0x38e430，GetVarLen为0x38e290，SetAlpha为0x38e14c，Mix_m128::ScaleInputPole为0x33c870。静态读取得到差值状态、16样本分组的float32乘加顺序，以及由差值平方的logf和四舍五入算出可变平滑长度。SetAlpha对数系数含1e-7稳定项，故逐样本epsilon停止假设不成立。静态代码不直接证明运行时调用归属；将相同运算顺序与实测系数匹配全部流，提供独立运行交叉验证。

`audio_pan.py`按测量得到的48kHz系数、128样本启动延迟、512样本外层块和16样本float32分组独立生成短增益前缀。目标系数由已测点一致的分贝量化模型产生；不读取原版输出作为生产查找表。3组完整PCM32逐字节相同，14组原版PCM24在引擎导出、保存重开及配置stdio MCP重放中均逐字节相同。MCP公开工具仍53个，`set_clip_properties`的properties新增pan字段。

引擎用float32增益流相乘后再应用float32自动边缘，修复原afade双精度系数导致的尾部1位差异。启动前缀完成后以补齐流和精确常量生成恒定尾部，辅助WAV大小与工程时长无关；临时目录由render的上下文清理。输入编号单独递增，防止多片段增益输入错配。旧工程缺失pan时默认为0；现有保存文件不自动重写。不同pan的相邻片段不抑制自动边缘，其通用原版连接规则仍未测。

本机308项通过、0失败/跳过，58.40秒。新增检查涵盖14个完整PCM24、3个完整PCM32内核、范围拒绝、旧工程/撤销/事务、多输入编号，以及现有UI测试中的控件写回。完整PCM24条件仍严格字节相同，没有放宽尾部容差。PCM32只是内核验证，产品MOV仍为PCM24，没有据此声称支持PCM32导出。

新增7组正弦/不同频率双声道和13/37/67等位置的原版波形实验脚本已准备，但桌面工具明确报告Mac锁定，尚未启动，不能计作验证。实际桌面声像控件也待解锁后验收；Qt测试不替代真实窗口结果。非48kHz下非零pan渲染明确拒绝，避免把未校准的采样率外推当作一致。完整目标继续开放。

Linux首轮CI295项通过、13项失败，均为非零pan输入路径的滤镜内存分配错误；内核检查通过。将单样本aloop改为apad/aeval恒定尾部填充，本机37项声像/增益/边缘专项再次全流通过。未调整PCM精确条件、跳过测试或替换Linux固定FFmpeg。修正后的完整和远程结果按对应提交收据独立核对。

默认系数的后续静态追踪已将拟合表达式替换为有初始化依据的0.99/0.2 float32幂，位值和已测输出不变；同时发现可写基数与旧运行分支，尚不能证明其他采样率。见[AUDIO-PAN-DEFAULTS.md](AUDIO-PAN-DEFAULTS.md)。
